## 승인 후 검증 필요

- 소유자 전용 독립 GAS 배포를 같은 배포 ID로 2.0으로 연결하고 실제 로그인 → 읽기 → 사용자 승인 범위의 저장 → DB revision → Docs 결과를 확인한다.
- 기존 계약 일정 4건의 event ID를 비공개로 백업하고 첫 marker 도입 후 생성 0건/동일 ID 갱신을 확인한다. 기존 mapping이 손상되면 수동 확인 후 진행한다.
- 실제 휴대전화의 Google 로그인, 브라우저 탭 복귀, 키보드/큰 글꼴, 외부 Docs·Calendar 링크, APK 설치를 확인한다.
- 스크린리더 실제 음성 탐색과 저사양 휴대전화 렌더링을 확인한다. 로컬 측정 수치를 기기 증거로 바꾸어 말하지 않는다.
- 운영 오류·quota는 격리 실패 주입과 구별한다. 실제 장애를 일부러 운영에 만들지 않는다.

## 다음 버전 권장

부분입금 원장은 [2.1.0 개발 계약](RECEIPT_LEDGER.md)에 따라 순수 계산·검증 기반을 구현했다. 현재 입력/저장/기존 수납 계산은 아직 연결하지 않았으므로 아래 1번 기능은 완료되지 않았다. 기존 과거 확인 원문, 새로운 실제 입금, 취소 참조와 날짜별 조회를 구분하며 화면·서버 이력 보호·백업/복원까지 연결한 뒤 사용 가능한 기능으로 검증한다.

| 우선순위 | 기능 / 구체적 개발 명세 | 위험·선행 조건 |
|---|---|---|
| 1 | 부분입금 원장: receipt ID, bill ID, 금액, 실제 입금일, 취소 참조; 기존 완납 도장은 별도 legacy source 표시 | 높은 효용, 높은 이관 위험. 기존 완납을 임의의 다회 입금으로 분해하지 않음 |
| 2 | 계약 적용일 이력: 현재 계약·최초 계약·갱신 합의·효력일·이전 조건의 불변 snapshot | 과거 고지서 불변과 월 중 변경 정책 별도 승인 |
| 3 | 실제 수입/예정 수입 추세 | 예정·발행·확인 입금의 별도 정의, 부분입금 원장 이후 신뢰성 증가 |
| 4 | 층별 운영 메모·수리 이력 | 관리자가 실제 사용하는 빈도 확인; 감사 이력과 삭제/보관 설계 |
| 5 | 증빙 연결 | 파일 ID/권한/보존 기간, 공유 범위 및 접근 오류 UX 필요 |
| 6 | APK 배포 채널 | Play 내부 테스트 또는 소유 HTTPS 채널 선택; 계정·비용·접근 제한 승인 |

## 효용 대비 비용이 낮아 제외

AI 상담·유료 분석 API, 임차인 자동 메시지 발송, 다중 사용자 권한 시스템, 즉시 TWA 전환은 현재 계정 전용 관리 흐름의 목적과 운영 부담을 고려해 제외했다. 메시지 미리보기/복사 기능은 유지하며 외부 발송은 사용자가 결정한다. 임차인 자료를 외부 AI 서비스로 보내지 않는다.

자동 다른 필드 병합도 제외했다. 다른 임차인 수정이라도 현재 전체 JSON의 과거 이력·금액을 원자적 단위로 다루므로 별도 3-way merge의 검증 없이 묵시적으로 병합하지 않는다. 충돌 비교, 후보 백업, 최신 자료 불러오기를 제공한다.
