# 고지서·분기 PDF 출력 — 웹 2.1.5

인쇄 화면에서 청구액·확인액·잔액·입금 원문을 유지하고, 입력·정정 등의 조작 요소를 숨긴다. 화면 UI와 JSON schemaVersion 1, 저장 방식과 공유 금액 규칙은 유지한다. 기존 GAS 검토 ZIP 2.1.4는 보존하며 이 웹 변경을 운영에 배포하지 않았다.

## 확인한 문제와 변경

2.1.4를 로컬 Edge에서 실제 PDF로 출력하자 입금 추가·기록 정정·개별 완납·원장 시작 버튼과 도움말이 종이에 남았다. 날짜와 버튼 문구가 겹치는 부분, 포커스된 키보드 이동 링크가 페이지 하단 내용에 겹치는 부분도 있었다. 긴 입금 메모 일부는 페이지 경계에서 나뉘었다. 짧은 분기 내역에는 화면용 최소 높이로 인한 추가 빈 페이지가 생겼다.

2.1.5에서 변경한 범위는 출력용 CSS와 기존 고지서 조작/도움말 영역의 클래스 두 종류다.

- 고지서 인쇄에서 모든 버튼과 기존 완납 조작 영역·원장 시작 도움말을 숨긴다. 청구 항목의 납부 상태·날짜, 청구/확인/잔액과 원장의 기록·정정 사유는 계속 출력한다.
- 인쇄에서는 키보드 이동 링크를 포커스 여부와 관계없이 숨긴다. 일반 화면에서는 기존 키보드 이동 기능이 유지된다.
- 한 페이지에 들어갈 수 있는 입금 기록은 페이지 사이에서 나누지 않는다. 한 페이지보다 긴 메모는 여러 페이지가 필요할 수 있다.
- 인쇄에서는 화면용 최소 높이를 없애 불필요한 빈 페이지를 방지한다. 월별 고지서는 A4 세로, 분기 내역은 A4 가로를 유지한다.

같은 익명 기존 고지서는 2페이지에서 1페이지로 정리됐고, 빈 분기 내역은 2페이지에서 1페이지가 됐다. 24건 입금·1건 사유 정정의 원장은 PC/모바일 각각 5페이지, 36명·108건의 분기 내역은 6페이지로 모든 항목을 유지했다. 원래 입금은 정정됨 표시와 함께 남고 정정은 실제 환급을 뜻하지 않는 기존 안내를 유지한다.

## 재실행과 증거

```powershell
npm run test:all
# PDF 출력만 재확인
npm run test:print
# 생성된 익명 PDF의 텍스트·페이지를 별도로 읽어 확인 (pdfplumber 환경 필요)
python tests/validate-print-pdf.py
```

`tests/print-browser.cjs`는 별도 임시 서버와 Edge 프로필에서 익명 자료만 사용한다. 포커스된 이동 링크와 버튼이 출력에서 숨겨지는지, PDF 생성 후 화면 조작 요소가 다시 표시되는지, 원문 저장 키와 원본 앱 키가 유지되는지, 외부 요청과 페이지 오류가 없는지 확인한다. 실제 자료 입력을 받지 않으며 기존 환경의 개인 자료를 읽지 않는다. 표준 전체 브라우저 검사에도 포함한다.

PDF 검증은 단순 파일 생성 확인을 넘어 모든 페이지의 텍스트·A4 방향·빈 페이지·페이지 밖의 글자·공유 규칙 금액을 확인한다. 입금 24건의 전체 메모와 정정 사유가 각각 한 페이지에 한 번만 나타나는지, 정정 버튼 문구가 기록으로 섞이지 않는지, 분기의 36개 호실과 108건 표시가 유지되는지도 확인한다. 실제 임대 자료가 포함된 PDF를 만들지 않는다.

Windows Codex의 번들 Python·pdfplumber와 Poppler를 사용하며 새 앱 의존성을 추가하지 않았다. `pdftoppm -r 110 -png`로 모든 페이지를 렌더링해 검토한다. 브라우저 검사 결과와 PDF는 Git에서 제외한 `test-results`에 생성하고 배포용 자료와 섞지 않는다. 검토용 PDF 4종은 `output/pdf`의 새 버전 파일에 보관한다. 해당 경로도 Git에서 제외하며 공개 검증 기록에 파일 해시를 남긴다.

최종 검증 소스는 `42539480399148687fa519fccc5d88c69e4c122b`다. `npm run test:all`에서 단위 **178/178**, 브라우저 묶음 **13/13**(인쇄 5개 포함) 통과. 전체 브라우저 수행은 2026-10-10T00:03:15.025Z–00:08:37.643Z, 한국 시간 09:03–09:08이다. PDF 5종의 18페이지 읽기 검사와 이미지 검토도 통과했고, 최종 전체 검사에서 생성한 모든 페이지 이미지가 직접 검토한 이미지와 일치했다. [검증 수·소스·PDF/이미지 해시와 운영 경계](../releases/development-2.1.5.json)를 보관한다.

## 실제 사용 범위

이 결과는 Windows Edge가 생성한 익명 PDF와 페이지 이미지에 대한 검증이다. 실제 프린터·휴대전화의 인쇄 창·드라이버와 Google GAS iframe에서의 인쇄는 아직 확인하지 않았다. 브라우저 인쇄 창의 머리글·바닥글·배율 등 사용자 설정에 따라 출력이 달라질 수 있다. 검사에서는 CSS 용지 크기를 따르고 브라우저 기본 머리글/바닥글은 끈다.

운영 데이터 저장·Docs 재생성·Calendar 실행·Google 업로드·배포·원격 push·Android 변경을 수행하지 않았다. 최신 개발 예시 미리보기는 http://127.0.0.1:4288/?demo=1 이다. 이전 포트의 사용자 입력과 설치 캐시를 지우지 않는다. 운영 반영 전에 실제 사용 환경의 인쇄/저장 흐름을 확인해야 한다.
