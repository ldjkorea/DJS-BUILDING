## 과거 기준 대조

읽기 전용 목록은 `.private/basis-review-20261010/queue.json`과 `README.md`에 있다. 검토 번호·고지서 월·임차인 ID·원문 해시·추정/누락 필드를 연결하며 원자료 출처와 확인 항목은 빈 상태다. 민감한 목록은 Git에 넣지 않는다.

```powershell
npm run prepare:basis-review -- .private/input.json 2026-10-10 .private/review-new
```

명시한 날짜와 유효한 원문을 검증하고 이 저장소 `.private` 아래의 새 폴더에만 출력한다. 기존 목록을 덮어쓰거나 앱 자료를 변경하지 않는다. 확인 내용을 기록해도 자동 확정/이관하지 않는다. 실제 정정은 기존 청구 기준 정정 화면에서 원문과 전후 금액을 별도로 검토한다.

접근 가능한 Drive의 `고지서`·`임대차`·`임대계약` 파일명 검색과 기존 자료 폴더 목록에서 대상 원문을 찾지 못했다. 모든 개인 폴더에 원문이 없다는 뜻은 아니다. 현재 현황 요약이나 대화 기록을 원래 발행 문서의 대체 근거로 사용하지 않는다.

## 실제 휴대폰과 인쇄 확인 순서

익명 예시를 사용하고 실제 자료를 입력하지 않는다. 새 검증앱 배포가 완료된 뒤 실행한다.

1. 본인 Google 계정으로 새 검증앱을 열고 소유자 외 계정 접근 제한을 확인한다.
2. 고지서 선택·원장 개시·부분입금 두 번·사유 정정·새로고침 후 재조회에서 합계와 이력이 일치하는지 확인한다.
3. 모바일 키보드가 열린 상태, 200% 글자, 가로/세로 회전에서 저장·취소 버튼과 오류 안내에 접근하는지 확인한다.
4. PWA 설치/오프라인은 정적 HTTPS 앱에서 확인한다. GAS iframe이나 Android 웹앱 실행기에서 PWA 오프라인까지 확인했다고 간주하지 않는다. 설치형 앱 업데이트 때 미저장 입력과 독립 저장 키가 유지되는지 확인한다.
5. 휴대폰 인쇄 메뉴에서 월 고지서와 분기 집계를 PDF로 저장한다. 이후 실제 프린터에서 금액·수납 이력·페이지 끊김·방향·누락을 확인한다.

현재 연결된 기기는 `sdk_gphone64_x86_64` 에뮬레이터이고 실제 휴대폰은 관측되지 않았다. 확인된 Windows 프린터는 Hancom PDF, Microsoft Print to PDF, OneNote다. 등록 목록을 실제 출력 증거로 사용하지 않는다.

계약 변경 적용일·이전/이후 조건, 월별 예정/발급 표시/입금일 기준 추세, 호실별 수리 비용·HTTPS 증빙 링크·사유 취소를 로컬 2.2.0에 구현했다. 기존 `audit`·고지서 snapshot·입금 원문을 보존하고 계약·수리 이력을 지우는 복원을 차단한다. 과거 예정액이나 날짜 없는 현금 흐름을 만들어내지 않는다. 범위와 제한은 [운영 기능 설명](OPERATIONS_2.2.0.md)에 있다. 실제 Google 저장·운영 배포·실기기 검증과 구분한다.
