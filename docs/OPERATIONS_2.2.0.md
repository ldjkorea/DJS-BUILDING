# 운영 이력·수입 추세 — 2.2.0

운영현황에 월별 수입, 수리·증빙, 계약 조건 변경 이력을 추가한다. 새 런타임 라이브러리는 없다. 기존 `audit`과 고지서 snapshot, 월세·관리비 VAT 및 실비 배분 규칙을 유지한다. 신규 배열은 선택 필드이며 기존 JSON에 빈 배열을 자동 추가하지 않는다.

## 계약 조건 변경

임차인 추가·수정·재계약 때 적용일과 사유를 입력한다. 실제로 달라진 조건에 대해 `contractChanges`에 기록 ID·임차인 ID·적용일·기록 시각·사유·이전/이후 조건을 남긴다. 기존 임차인 `audit`도 계속 기록한다. 금액의 숫자 문자열 표현만 달라지는 경우는 새 조건 변경으로 취급하지 않는다.

적용일은 실제 날짜이고 기록일 이후일 수 없다. 이번 기능은 **적용했던 날짜를 남기는 이력**이다. 미래 조건 예약·자동 적용·일할 계산은 지원하지 않는다. 기존의 현재 임차인 조건 저장은 유지하며 이미 저장된 고지서·입금 원장은 당시 snapshot을 사용한다. 기록 이전의 과거 계약을 만들어 채우지 않는다. 운영현황에서 최신 20건을 표시하고 전체 이력을 JSON 백업에 보존한다.

## 월별 수입 추세

연도를 선택해 12개월을 비교한다. 공통 `RentalBilling` 계산을 사용하며 조회만으로 저장하지 않는다.

| 열 | 계산 근거 |
|---|---|
| 예정 월세·관리비 | 현재·미래 월의 현재 계약 공급가에 기존 VAT 규칙을 적용. 해당 월과 계약기간이 겹치는 임차인만 포함. 공실/보관은 제외. 과거 월은 근거 없음. 계약기간을 읽을 수 없는 경우 확인 필요 건수 표시 |
| 발급 표시 청구액 | 해당 고지서 월의 `invoiceIssued === true`인 저장 고지서. 이 플래그는 기존 **세금계산서 발급 표시**다. 전체 임대 현금 수입이나 전자세금계산서 서비스의 발급 증거를 뜻하지 않음 |
| 새 입금 기록 | 입금 원장의 취소되지 않은 receipt. 고지서 월·연도와 관계없이 `receivedOn`의 월에 합산. 조회 기준일에 아직 기록되지 않은 취소는 소급 반영하지 않음 |
| 날짜 있는 과거 확인 | 기존 완납/항목별 확인과 원장 개시 때 보존한 과거 확인 중 날짜가 있는 금액. 새 입금과 중복 합산하지 않음 |
| 날짜 미지정 과거 확인 | 선택 연도 고지서의 날짜 없는 과거 확인. 별도 합계이며 월별 현금 흐름에 넣지 않음 |

예정액에는 아직 정산되지 않은 공과금을 임의로 0원이라고 확정해 합산하지 않는다. 정정 기록의 취소는 현금 반환을 자동 실행하지 않으며 실제 환급이나 다른 달 배분과 구분한다. 원장 이후 청구액 조정은 별도 운영 정책 응답을 기다리는 상태다.

## 수리·증빙

호실 또는 공용 구역, 날짜, 원 단위 비용, 내용, HTTPS 증빙 링크를 저장한다. 링크에 인증정보가 들어 있거나 실행 가능한 URL 스킴이면 거절한다. 링크 저장만으로 파일 업로드·공유 권한 변경·외부 URL 요청을 수행하지 않는다. 사용자가 링크를 열 때 본인 권한으로 접근한다.

지출에 같은 비용이 자동 추가되지는 않는다. 기존 지출에서 이미 기록한 건도 중복 집계 없이 증빙 이력으로 남길 수 있다. 필요할 때 지출은 기존 화면에서 별도로 입력한다.

잘못된 수리 기록은 사유가 있는 `void`를 추가해 취소 표시한다. 원래 기록의 내용·비용·증빙은 그대로 보존하고 실제 환급을 실행하지 않는다. 호실별 최신 50건을 표시하며 전체 `propertyRecords`는 JSON 백업에 포함된다. 작성 중 입력은 화면 이동·저장 실패 시 메모리에서 유지하지만 새로고침 뒤의 미저장 수리 입력 복원까지 지원한다고 표시하지 않는다.

## 저장과 서버 보호

기존 localStorage 한 번의 쓰기, Web Locks, 원문 토큰, 다른 창 충돌 확인, 실패 시 직전 저장 복구를 재사용한다. 계약·수리 기록은 이미 저장된 배열의 prefix를 바꾸거나 줄일 수 없다. 오래된 백업으로 새 이력을 지우는 복원도 차단한다. 새 기기에서는 전체 이력이 있는 백업을 읽을 수 있다.

클라이언트와 GAS가 `rental-operations-v1` 보호 능력을 확인한다. 이력이 있는 자료를 지원하지 않는 서버로 업로드하지 않으며 구형 클라이언트의 GET/POST도 안내와 함께 차단한다. 서버의 revision·requestId·중복 요청·LockService·쓰기 전 복구 백업·저장 후 재조회 보호를 유지한다. DB 저장 성공과 Docs 생성 결과는 계속 구분한다.

## 검증 범위

익명 단위 검사는 원문 보존, 적용일·날짜·원 단위 금액·URL·중복/취소 순서, 배열 prefix와 오래된 복원 차단, 고지서 연도와 다른 실제 입금일, 취소의 기록 기준일, 미발급·날짜 없는 과거 확인·과거 예정액 구분 및 생성 GAS 계산 일치를 확인한다. 서버 검사에서는 보호 프로토콜·중복 재시도·원문/복구·잘못된 prefix·동시 저장을 확인한다.

새 Edge 묶음은 PC/모바일 수리 저장·재조회·취소·증빙 실행 방지, 실패 후 같은 ID로 재시도, 계약 변경 후 과거 고지서와 기존 audit 보존, 미래 적용일 거절, 구형 서버 업로드 차단, 원문 제거 차단, 4개 폭×100%/200% 글자·키보드를 확인한다. 전체 기존 회귀와 출력 결과는 [후속 마무리 상태](FOLLOWUP_FINISH.md)와 별도 검증 JSON에 기록한다. 현재 실제 운영 주소의 업그레이드·Google 실제 쓰기·실기기·물리 프린터 증거를 포함하지 않는다.
