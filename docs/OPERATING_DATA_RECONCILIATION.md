# 독립 운영 자료의 읽기 전용 대조

웹 2.1.3 검토 후보의 계산이 독립 운영 자료에서 기존 계산과 일치하는지 확인한다. 앱 코드·저장 형식·운영 자료를 수정하거나 운영 배포하지 않는다. 계산 일치를 과거 청구 기준 확인 또는 운영 준비 완료로 해석하지 않는다.

## 최신 자료 대조 결과

2026-10-10 독립 Google 시트의 sheetId 0과 표시 이름을 metadata로 확인하고, JSON이 저장된 A열만 읽었다. 20행의 초기 범위를 확인한 뒤 metadata의 1,000행 범위에서 전체 원문을 확보했다. 저장 원문은 35,000자 단위의 3개 행이다. 재조회에서도 원문이 같았다. 개인정보가 있는 입력과 상세 결과는 Git 제외 `.private`에 보관한다.

운영 GAS의 Billing 소스를 GET으로 조회해, 생성 주석 한 줄과 줄바꿈만 제외하면 복제 기준 `2b01a2e`의 `assets/billing.js`와 같음을 확인했다. 이 기준으로 새 로컬 공유 계산과 생성된 GAS 계산을 비교했다.

| 검사 | 결과 |
|---|---|
| 등록 임차인 / 저장된 월 / 비어 있지 않은 고지서 | 4 / 11 / 38 |
| 비교 기준일 | 165개. 명시한 기준일과 납기·납부일 전날/당일/다음 날 |
| 고지서 × 날짜 × 6개 항목 | 37,620개 항목 대조 |
| 기존 계산과 새 계산 차이 | 0건 |
| 새 공유 계산과 생성 GAS 계산 차이 | 0건 |
| 체납 총계·임차인 수납 상태 차이 | 0건 |
| 분기 집계와 해당 분기 저장 고지서 합계 | 660개 대조, 차이 0건 |
| core 검증의 필드 보정 / 보정에 따른 금액 차이 | 0 / 0 |
| 로컬 GAS 서버 validator의 입력 수용과 원문 보존 | 통과. 실제 Google 실행은 아님 |
| 기존 과거 추정 표시가 있는 고지서 | **30건. 원래 고지서·계약 자료 대조 필요** |
| 필수 snapshot 누락 / 입금 원장이 있는 고지서 | 0 / 0 |

계산 비교는 통과했지만, 추정 기준 30건이 남아 있어 `reviewRequired: true`다. 추정 표시는 제거하지 않는다. 실제 입금 원장을 가진 운영 자료는 현재 0건이므로, 이번 실제 자료 대조는 새 원장의 운영 저장·복원 증거가 아니다. 원장의 부분입금·잘못된 구형 baseline 거절은 익명 단위 검사로 확인한다.

공유용 [대조 증거](../releases/reconciliation-2.1.3.json)는 검사 개수·소스 해시·읽기 확인·남은 검토만 담는다. 임차인 이름·ID·연락처·계약 내용·실제 금액·상세 원문을 포함하지 않는다.

## 재실행

입력은 기존 JSON 백업, `rental-sync-storage-v2` 저장 envelope, 또는 Sheets A열의 `values` 응답을 지원한다. 다음 명령의 입력 파일과 결과 파일은 본인 컴퓨터의 `.private`에 둔다. 기준일은 YYYY-MM-DD로 명시하고 Git 기준 ref는 신뢰할 수 있는 해당 운영 계산 소스로 지정한다.

```powershell
npm run reconcile:data -- .private/input.json 2026-10-10 2b01a2e .private/report-new.json
```

- 입력은 메모리에서 복제하며 원본 파일·브라우저 저장소·Google 서비스에 쓰지 않는다. 이 명령에는 인증·네트워크 호출이 없다.
- 출력은 이 저장소 `.private` 안의 새 파일로 제한한다. 기존 결과 파일은 덮어쓰지 않는다.
- 종료 코드 0: 계산 차이·보정·추정 기준 검토가 없다. 운영 준비 완료 판정은 아니다.
- 종료 코드 2: 비교는 실행됐지만 차이·보정 또는 과거 기준 검토가 필요하다. 이번 실제 자료는 추정 30건 때문에 2다.
- 종료 코드 1: 입력·기준 코드·날짜·출력 경로 등에 문제가 있어 비교를 완료하지 못했다.

입금 원장이 있는 입력에 이를 지원하지 않는 구형 기준 코드를 지정하면 비교를 거절한다. 기존 코드가 원장을 무시한 결과를 정상 비교로 보고하지 않는다. 납부 항목의 금액·확인액·미납액·날짜·미부과·상태·납기, 고지서 합계와 체납·수납 상태를 모두 비교한다. `null`·추가 필드·변경 이력을 검증 후 자동 보정하는 경우에는 해시와 필드 경로를 기록해 별도 검토 대상으로 남긴다. 비공개 상세 결과의 `invoiceIndex`는 검토용 번호와 원래 고지서 월·임차인 ID를 연결하므로 실제 자료를 찾아 검토할 수 있다. 이 연결 목록은 공유용 증거에 포함하지 않는다.

단위 검사에서 미래 날짜·날짜만 달라지는 경우·합계만 달라지는 경우·원장 부분입금·GAS 차이·분기 합계 차이·누락/추정 기준·고아/보관 고지서·손상 입력·기존 결과 보호를 확인한다. 새 대조 검사 12개와 전체 단위 검사 177개가 통과했다. 앱·금액 규칙·UI 소스는 변경하지 않았으므로 이번에 전체 브라우저 묶음을 재실행하지 않았다. 앞선 ZIP 화면 검사 결과는 별도 기록으로 유지한다.

## 남은 확인

이 검사는 현재 저장된 JSON을 같은 기준으로 계산하는지 확인한다. 웹앱 전체 초기화·모든 기기 복원·입금 원장 개시·실제 Google 쓰기·Docs/Calendar·설치/오프라인/인쇄를 실행하지 않는다. 각 과거 추정 기준은 원래 발행 고지서나 계약 자료로 확인해야 한다. 아직 없는 자료에서 값을 만들어 확정하지 않는다. 원장 개시 전 정정은 별도 저장으로 검토하며 이미 시작된 원장 기준 변경은 이관 정책 없이 허용하지 않는다.

직접 Google Sheets REST API는 현재 OAuth 프로젝트에서 비활성화된 응답을 받았다. API 설정을 변경하지 않고 Google Drive 플러그인의 metadata/범위 읽기로 최신 자료를 확보했다. 이 읽기 경로의 문제를 이미 완료한 GAS 앱 권한 승인 실패로 해석하지 않는다.
