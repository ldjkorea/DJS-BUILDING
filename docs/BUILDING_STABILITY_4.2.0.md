# NEW RENT STORE 4.2.0 안정화 후보

개인 건물 한 채의 계산 정확성과 기존 기록 보존을 위한 개발 후보다. 운영 GAS 교체, 운영 데이터 쓰기, APK 공개는 아직 수행하지 않았다. 최종 검증 수치와 상태는 `releases/stability-4.2.0-validation.json`에 기록한다.

## 조사 기준과 버전

- 최초 원격 기본 브랜치: `work/independent-v2`, `eb1e3c776c7949405cd763deb3a6d95facdee8c8`.
- 기존 릴리스: `v4.1.2`, `45d055bd3cab04cff6db188f627ea885b0528857`. 보존한다.
- 후보: Android 4.2.0 / versionCode 8, 웹 2.4.0. 패키지, 서명, 암호화 저장소, 독립 웹 저장 키를 유지한다.
- 작업 브랜치: `work/building-stability-20261011`. 원본 RENT STORE 및 2025 RENT STORE에는 수정·푸시하지 않는다.

## 수정한 결함과 기존 자료 영향

| 결함 | 원인과 수정 | 기존 자료 영향 |
|---|---|---|
| Windows 생성 HTML 불일치 | SVG를 base64로 넣기 전 UTF-8 줄바꿈을 LF로 정규화한다. `scripts/build.cjs`에서 생성하며 생성 파일을 직접 수정하지 않는다. 같은 4.1.2 소스로 CRLF 입력 시 4바이트 차이를 재현했다. | 아이콘 내용과 금액 계산 불변 |
| 4층 보관 후 정산 중단 | `RentalBilling.calculateBuilding`에서 실제 건물 구조와 점유 임차인을 분리한다. 기존 `calculate`를 사용해 배분한 뒤 공실 부분을 별도 `ownerCandidates`로 표시한다. 후보에는 임차인 ID가 없고 고지서를 만들지 않는다. | 과거 고지서·원장 불변. 정책 미확정 비용은 확정 차단 |
| 공실 비용이 다른 층으로 넘어갈 가능성 | 2·3층 전기 공급가 35,000원, 4층 잔액을 유지한다. 보관된 5층의 기존 공용비 대상과 실측 사용량도 검토 대상으로 남긴다. 1층 승강기 제외 규칙은 유지한다. | 임대인 후보가 체납에 합산되지 않음 |
| 달만 기준으로 한 계약 경계 검토 | `reviewAllocationPeriods`가 실제 전기·수도 사용기간과 입주·계약 종료·퇴거·부담 종료 경계를 검사한다. 월초 입주라도 전월 사용기간이 겹치면 수동 검토한다. | 일할 금액이나 부담 정책을 자동 생성하지 않음 |
| 수도 소수점·음수 처리 차이 | `normalizeWaterFloors`를 웹과 GAS가 함께 사용한다. 계량기 차이는 소수 셋째 자리까지 계산하며 역전·음수를 거부한다. 실제 유효한 기존 계산 결과를 대조한다. | 저장된 계량기·고지서를 다시 계산해서 덮어쓰지 않음 |
| Android 고지서 발행과 세금계산서 혼동 | 버튼을 외부 세금계산서 발급 완료 확인으로 바꾸고 서버에 `taxInvoiceVerified=true` 명시 확인을 요구한다. PDF와 발급 상태는 분리한다. | 기존 `invoiceIssued` 의미와 이력 유지, 자동 교정 없음 |
| 익월 납기 오류 | `dueDate`가 고지서 기준 월에 익월 오프셋을 적용한 뒤 월말을 보정한다. 윤년·연도 변경·납기 당일/다음 날을 검사한다. | 기존 날짜·확인 기록·납기 snapshot을 마이그레이션하지 않음 |
| Android 입금 정정 경로 부족 | 원장 원본 목록, 필수 사유, 저장 전 잔액 검토와 확인을 추가한다. `prepareReceiptVoid`, `expectedRevision`, `requestId`, preview hash와 기존 append-only 검증을 재사용한다. | 원본을 삭제·덮어쓰지 않고 void 이벤트만 추가. 실제 환급을 기록하지 않음 |
| 동일 정산 재확정 | `allocationSnapshot`과 기존 확정값을 비교해 같은 입력·배분의 중복 저장을 거부한다. 다른 배분도 기존 입금 원장을 바꿀 수 없다. | 과거 확정 자료에 snapshot을 소급 추가하지 않음 |
| PWA 이전 캐시 재생성 | 이전 worker의 늦은 fetch에서 `caches.open` 대신 이름 지정 읽기만 한다. 활성화 후 삭제된 이전 캐시를 다시 만들지 않는다. 외부 요청 차단과 실제 lifecycle 검사를 유지한다. | 운영 JSON·독립 저장 키 불변 |

## 추가한 최소 운영 편의 기능

- `buildingOverview`: 실제 1~5층을 기준으로 공실을 한 번만 집계한다. 층 운영 상태와 임차인 상태 중복 기록으로 공실이 두 번 증가하지 않는다. 기존 수리 기록의 건수·최근 일자를 읽기 전용으로 요약한다. 지하·옥상은 기존 수리 구역 필터로 확인하며 임대층에 합산하지 않는다.
- 계약 확인 예정일: `contractReviewOn`과 감사 메모만 저장한다. 현재 계약, 월세, 보증금, 계약 변경 원장, 고지서, Calendar를 자동 적용하지 않는다. 웹의 기존 업무 영역과 Android 계약 화면을 재사용한다.
- 수리·지출 대조: 같은 날짜·금액의 기존 지출을 표시한다. 같은 비용인지 증빙을 확인하는 보조 정보이며 동일 거래라고 단정하거나 지출을 자동 추가하지 않는다.
- 보관된 임차인의 과거 고지서도 Android 입금 정정·출력 선택 목록에서 접근할 수 있다. 새 서버 기능이 없으면 입금 정정 저장 경로를 열지 않는다.
- Android 입력 초안은 기존 암호화 저장을 사용한다. 저장 중 중복 클릭 차단, 확인 절차, 실패 후 입력 보존, 최신 서버 재조회와 지연 응답 보호를 재사용한다. 전체 UI 재작성이나 새 런타임 의존성을 추가하지 않는다.

## 재현 가능한 검사

```powershell
npm run test:all
npm run check:build
python tests/validate-print-pdf.py
```

공식 회귀검사는 15개 브라우저 suite와 감사 검사 69개 전체를 유지한다. 로컬 자원 부족 시 `RENTAL_AUDIT_WORKERS=1`을 사용할 수 있다. CI 기본값은 2이며 모든 shard와 동일 assertion을 실행한다.

```powershell
./android/gradlew.bat -p android :app:assembleRelease :app:lintRelease :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

서명 설정은 기존 `.private/android-signing.properties`를 사용하며 값을 출력하거나 Git에 포함하지 않는다. 설치된 버전 코드가 증가하면, 먼저 `node scripts/prepare-android-update-fixture.cjs`로 더 높은 버전의 QA APK를 갱신한다. 스크립트는 원본 Gradle 파일을 private 디렉터리에 보관하고 `finally`에서 복원한다. QA APK는 androidTest assets에만 들어가며 배포 APK에는 포함되지 않는다.

전용 `rental-stability-qa` AVD의 serial을 확인한 뒤 debug APK와 test APK를 설치하고 AndroidJUnitRunner를 실행한다. 다른 프로젝트 AVD나 실제 휴대전화의 자료를 초기화하지 않는다. 정상 suite에서 공개 업데이트·공개 APK 확인과 수동 업그레이드 probe는 조건부 제외되며 이 수를 성공 수와 구분한다.

`UpgradePreservationProbe`는 별도로 code 7에서 `mode=seed`, 후보 덮어 설치 후 `mode=check`를 실행한다. 합성 토큰, 고지서 캐시, 암호화 원문 해시, 최초 설치 시각, 설치 APK 해시를 비교한다. Google 호출은 하지 않는다. 이는 실제 S26·One UI 및 공개 업데이트 버튼으로 다운로드하는 검증과 다르다.

## 운영 자료 읽기 전용 대조

별도 운영 시트의 JSON을 작업 시작과 검증 시점에 읽기만 한다. 과거 릴리스와 후보·생성 GAS의 고지서별 청구, 수납, 납기, 체납, 분기 결과를 비교한다. 개인정보 원문과 상세 보고서는 `.private`에 보관한다. 공개 검증 JSON에는 건수·차이 수·해시만 기록한다.

현재 납기 표현은 당월 08·10·15·20일이다. 익월 입력은 현재 운영 자료에서 확인되지 않았다. 따라서 계약과 충돌하는 운영 데이터 변경을 수행하지 않는다. 기존 청구 근거가 추정인 고지서 30개는 별도 원문 확인 대상으로 보존한다. 비교 차이 0은 그 근거까지 새로 확정했다는 뜻이 아니다.

## 실패 기록과 재검증 원칙

- 기존 4.1.2 CI 생성물 검사를 삭제하지 않는다.
- P0 후 synthetic demo에 전기·수도 기준일이 없어서 확정이 차단된 실패는 demo fixture에 명시 기준일을 추가해 해결했다. 운영 기준일을 자동 지정하지 않는다.
- PWA lifecycle 실패 중 이전 캐시 재출현을 재현해 worker의 캐시 생성 경로를 수정했다. 로컬 요청 interception 영향을 줄여 실제 worker를 직접 검사하며 외부 요청 차단은 유지했다.
- 웹 버전이 2.4.0이 되면서 업데이트 검사에 고정된 다음 버전 2.4.0은 새 버전이 아니었다. 현재 버전보다 높은 시험값으로 바꾸고 알림·데이터 보호 검사를 유지했다.
- Android 기존 fixture가 후보보다 낮거나 형식이 맞지 않아 거부된 실패는 다음 버전 fixture를 다시 서명해 해결했다. APK 해시·인증서·버전·손상 차단 검사를 완화하지 않았다.
- 작은 AVD의 보이는 버튼 개수를 가정한 검사는 실제 보이는 버튼을 선택하도록 바꿨다. 지연 상태의 읽기 허용·쓰기 차단 assertion을 유지했다.
- 코드 보완 중 실행되던 전체 검사 결과는 최종 소스의 증거로 사용하지 않고 보관한 뒤, 고정된 최종 소스에서 다시 실행한다.

## 남은 제한

1. 공실·월 중 점유 변경의 최종 비용 부담과 일할 계산 정책은 사용자가 확인해야 한다. 후보를 임차인이나 임대인 확정 원장으로 자동 저장하지 않는다.
2. 과거 추정 청구 근거와 과거 `invoiceIssued`의 외부 세금계산서 발급 사실은 이 검사로 소급 인증할 수 없다.
3. 실제 Google 저장·복원·Calendar·Docs 변경 검증은 승인 전 수행하지 않는다. 모의 검증 결과와 운영 읽기 대조를 구분한다.
4. 실제 S26·One UI의 설치 허용, 키보드·회전, 불안정 네트워크, 시스템 인쇄·공유는 `PHYSICAL_DEVICE_STABILITY_CHECK.md`에 따라 별도 확인한다.
5. Kotlin Activity 중심 구조와 기존 lint 경고는 남아 있다. 검토·정정 기능과 서버 요청 경계를 분리했으며 Compose 이전이나 스타일 목적의 전면 변경은 하지 않았다.
