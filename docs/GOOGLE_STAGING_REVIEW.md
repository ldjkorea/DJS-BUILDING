# 별도 Google 검증앱 계획 — 2.1.5

현재 로컬 검증을 통과한 [GAS 2.1.5 후보](GAS_REVIEW_CANDIDATE_2.1.5.md)를 실제 Google iframe·저장·문서·Calendar 흐름에서 확인하기 위한 계획이다. 기존 운영 대상 대신 **새로 만든 검증용 Google 자원과 익명 자료**를 사용한다. 사용자의 후속 마무리 요청으로 새 Sheet·Doc·연결 GAS와 최초 권한 승인용 bootstrap을 준비했다. 새 프로젝트의 Google 최초 권한 승인 응답을 기다리고 있으며 Calendar 생성·제품 전체 업로드·배포·실제 익명 저장 검사는 아직 실행하지 않았다. 현재 자원과 제한은 [마무리 상태](FOLLOWUP_FINISH.md)에 기록한다.

## 생성할 대상

현재 독립앱의 Google 소유자 계정으로 다음 자원을 각각 하나씩 새로 만든다. 구분 가능한 생성 식별자를 붙이고 같은 생성 시도의 응답이 불확실하면 먼저 생성 여부를 확인한다. 공개 공유는 하지 않는다.

| 대상 | 이름 기준 | 내용 |
|---|---|---|
| GAS 프로젝트 | 임대관리 독립앱 2.1.5 검증용 - GAS | 검증한 소스를 새 대상에 연결, 소유자만 접근하는 배포 |
| Google Sheet | 임대관리 독립앱 2.1.5 검증용 - DB | 새 빈 저장소로 시작해 익명 검증 자료만 저장 |
| Google Doc | 임대관리 독립앱 2.1.5 검증용 - 현재현황 | 검증용 DB의 상태를 출력 |
| Google Calendar | 임대관리 독립앱 2.1.5 검증용 - 계약일정 | 익명 계약의 일정 생성·변경·삭제 확인 |

실제 운영 자료·연락처·입금 내역을 복사하지 않는다. 기존 Google 파일의 권한과 내용, 기존 GAS 소스/배포, 원본 앱/원본 저장소는 이 환경 생성의 변경 대상이 아니다. 검증용 파일과 결과는 남겨 이후 확인할 수 있게 한다.

## 바인딩할 소스 범위

현재 후보 ZIP은 기존 독립앱의 대상 ID를 담고 있다. 새 환경에는 복원한 별도 소스 사본만 사용하며 다음 항목을 바꾼다.

- `Code.gs`: `INDEPENDENT_SPREADSHEET_ID`와 새 시트 metadata로 확인한 `INDEPENDENT_SHEET_ID`.
- `CurrentStatus.gs`: `STATUS_DOCUMENT_ID`와 검증용 문서 제목.
- `CalendarSync.gs`: `INDEPENDENT_CONTRACT_CALENDAR_ID`.
- `App.html`: 검증용 제목/표시, 새 검증 웹 주소, 별도의 `STORAGE_PREFIX`.

브라우저 저장 접두사는 `rentalIndependent20261009.staging215.<생성식별자>.`를 사용해 같은 브라우저에서도 기존 독립앱 저장 키·Web Locks·초안/복원 정보와 구분한다. 새 주소가 확정되기 전에는 기존 운영 URL을 기본 연결로 남기지 않는다. 원본 ZIP과 검증된 개발 소스를 직접 수정하지 않으며 새 바인딩 파일과 해시를 별도로 기록한다. 변경은 위 연결·표시 범위로 제한하고 계산·조건부 저장·원장 프로토콜은 유지한다.

업로드 전 새 자원 ID가 기존 운영/원본 대상과 모두 다른지, 소유자가 맞는지, 복원한 소스가 운영 ID/URL을 가리키거나 기존 물리 저장 키를 사용하지 않는지 확인한다. 저장 접두사의 공통 문자열이 아니라 완성된 물리 키와 잠금 이름이 분리됐는지를 검사한다. 바인딩 파일의 차이가 위 허용 범위를 벗어나면 업로드를 멈추고 원인을 확인한다. 새 자원 ID·소스 해시·배포 버전과 테스트 결과를 보관한다.

## 확인할 실제 흐름

1. 소유자 로그인과 새 프로젝트의 권한, 검증앱 표시와 빈 DB 첫 조회를 확인한다.
2. 익명 고지서 저장 후 다시 불러와 JSON·revision을 대조한다. 같은 requestId 재전송이 중복 입금이나 이력을 만들지 않는지 확인한다.
3. 다른 창/다른 revision의 충돌을 확인하고 최신 DB가 덮어써지지 않는지 재조회한다. 원장 개시·부분입금·사유 정정·호환 백업 복원을 확인한다.
4. 실제 Google Doc의 출력과 저장 결과를 각각 확인하고 재실행 결과를 기록한다. DB 성공을 문서 성공으로 대신 표시하지 않는다.
5. 새 Calendar에서 익명 계약 일정의 생성·변경·삭제와 저장된 event ID를 확인한다. 다른 Calendar에는 쓰지 않는다.
6. 실제 GAS 화면에서 고지서·분기 CSV와 PDF 출력을 확인한다. 테스트 전후 기존 운영 소스/배포/JSON이 유지됐는지도 읽기 전용으로 대조한다.

Google의 실제 권한 창 또는 로그인 확인이 필요하면 해당 절차에서 진행한다. 사용자 비밀번호나 인증 코드를 대신 입력·보관하지 않는다. 실제 휴대전화와 프린터는 이 별도 Google 브라우저 검사에서도 추가 확인 대상이다.

이 계획의 승인은 **검증용 자원 생성·소유자 전용 배포·익명 자료의 실제 저장/문서/Calendar 검사** 범위다. 기존 운영 앱의 2.1.5 반영이나 실제 임대 자료 변경 승인을 포함하지 않는다. 기존 운영 반영은 이 검증 결과와 복구 절차를 확인한 후 별도로 판단한다.
