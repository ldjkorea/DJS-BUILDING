# GAS 2.1.3 검토 후보

이 후보는 웹 2.1.3의 입금 원장·분기 집계·원장 개시 대조·원장 전 청구 기준 정정 소스를 담는다. **운영 배포 전 검토용**이며 실제 운영 준비 완료 판정은 아니다. 운영 앱 1.0 / 배포 버전 4, 이전 후보 ZIP, Android 2.0.0 APK를 보존한다.

## 산출물과 출처

- [GAS ZIP](../releases/rental-independent-gas-2.1.3.zip)
- [파일별 해시와 출처](../releases/gas-candidate-2.1.3.json)
- [압축본 검사 결과](../releases/validation-gas-candidate-2.1.3.json)
- 제품 검증 소스: `e08f915`. 패키징 도구와 후보 출처: `8345a8a`.
- 실행 전 제품 소스 대조 보완: `21afa67`. 기존 ZIP 바이트와 후보 생성 출처는 유지한다.
- ZIP: 1,704,106 bytes. SHA-256: `46e4f65eab6cbf69344aae34d3ac245c1bc5c66cea3b7392b8ce8c87d0648e10`.

포함 파일은 `App.html`, `AuthorizeDocs.gs`, `Billing.gs`, `CalendarSync.gs`, `Code.gs`, `CurrentStatus.gs`, `IndependentApp.gs`, `appsscript.json`의 8개다. 실제 임대 자료·OAuth 설정·서명키·`.clasp.json`은 포함하지 않는다. 시트·문서·Calendar 대상과 Google 권한 범위는 검증한 독립 GAS 소스와 동일하다. 실행 계정은 배포자, 공개 범위는 소유자만이다.

ZIP은 이 컴퓨터의 로컬 산출물이다. Google 업로드·배포·원격 push·Drive 공유를 하지 않았다. ZIP은 Git에서 제외되며 manifest·검증 결과·생성 도구는 Git에 기록한다.

## 재실행

Node와 PowerShell 7이 필요하다. 기본 PowerShell 실행 파일은 `pwsh`이며 필요한 경우 `RENTAL_PWSH`로 경로를 지정한다. 새 런타임 라이브러리를 추가하지 않고 .NET의 ZIP 생성·읽기를 사용한다.

```powershell
npm run check:build
npm run package:gas
npm run test:gas-candidate
```

첫 생성은 소스가 커밋돼 있고 검증 기록과 일치해야 한다. 제품 파일은 기록된 SHA-256과 대조하고, 모든 GAS 파일은 제품 검증 커밋의 내용과 대조한다. package.json의 버전도 검사한다. 패키징 도구의 npm 명령 추가는 제품 코드 변경으로 취급하지 않으며 제품 검증 기록의 다른 파일은 계속 대조한다.

다시 실행하면 기존 ZIP·manifest를 검증해 재사용한다. 소스가 달라졌거나 파일 하나만 존재하는 불완전 후보는 덮어쓰지 않는다. 새 소스에는 새 버전과 그 버전의 검증 기록이 필요하다. 압축 시 파일 순서·시각을 고정해 같은 도구 실행 환경에서는 같은 바이트가 나온다. 다른 .NET 압축 구현까지 같은 ZIP 해시를 보장하는 주장은 하지 않는다.

검증 명령은 ZIP을 다시 읽고 별도 임시 폴더에 정확한 8개 파일을 복원한다. 파일명·중복·크기·내용 해시·GAS 문법·소유자 전용 설정을 검사한다. 해당 GAS 코드로 Sheet·Docs·Calendar 모의 검사를 실행하고, ZIP의 App.html만 제공하는 localhost에서 입금·원장 대조·청구 기준 정정·분기 화면을 검사한다. 저장소는 익명 자료와 별도 Edge 프로필을 사용하며 외부 요청을 차단한다.

ZIP과 manifest가 함께 변조돼 서로의 해시가 맞는 경우에도, 실행 전에 각 파일을 검증 기록과 제품 커밋에 대조한 현재 소스와 비교한다. 두 파일을 함께 변조한 검사는 일반 무결성 검사 통과 후 제품 소스 대조에서 거절되는지 확인한다.

이 ZIP에는 PWA의 정적 파일 15개가 들어 있지 않다. PWA 설치·오프라인 캐시는 앞선 제품 소스 검증의 증거이며 ZIP을 실행한 검증으로 대신하지 않는다. Google의 실제 iframe·소유자 로그인·권한·저장·문서·Calendar 종단 동작도 모의 검사로 완료 판정하지 않는다.

최종 검사: 전체 단위 165/165(새 패키징 7개), 압축본 GAS 모의 서비스 42/42, 압축본 화면 38/38(입금 11·원장 대조 8·청구 기준 정정 11·분기 8). 실행 전 제품 소스 대조 보완 후 압축본 검사 수행 시각은 2026-10-09T23:09:30.733Z–23:10:47.139Z다. 소스의 문법·생성 파일 일치도 통과했다. 같은 실행 환경의 두 ZIP 바이트 일치, 기존 파일 덮어쓰기 거부, 허용 목록·경로 조작·해시 손상·검증된 소스 변경·ZIP과 manifest 동시 변조 거부와 압축본 GAS 문자열 전송의 nested null·원장 프로토콜도 검사했다.

## 이관과 롤백 경계

| 상황 | 현재 지원과 필요한 확인 |
|---|---|
| 기존 고지서에 원장 없음 | 기존 JSON 형식 유지. 누락된 과거 값은 추정으로 표시한다. 실제 전체 월별 금액·날짜 대조는 아직 필요하다. |
| 원장 시작 전 청구액·계약 정정 | 전후 대조·사유·원문 이력과 함께 별도로 저장한 후 원장을 시작한다. 같은 저장에서 정정과 개시를 합치지 않는다. |
| 기존 원장 있는 백업 | 청구 기준·header·기록 prefix를 유지하는 복원만 허용한다. 오래된 백업으로 기록을 지우는 복원은 차단한다. |
| 원장 시작 후 청구액·계약 변경 | 현재 지원하지 않는다. 이미 받은 실제 입금·감액·초과 확인액·미부과 변경의 이관 정책을 먼저 정해야 한다. 원장 기준 잠금을 해제하지 않는다. |
| 구형 클라이언트 | 서버는 원장이 있는 자료에 `rental-receipts-v1` 프로토콜을 요구한다. 지원하지 않는 읽기·쓰기는 차단될 수 있어 사용 기기의 업데이트를 확인해야 한다. |
| 예전 서버로 롤백 | 새 원장을 저장한 뒤 원장 보호가 없는 1.0/2.0.6 서버로 단순 롤백하면 이력 보호를 보장할 수 없다. 원장 지원 소스와 모든 기록을 유지하는 복구를 준비해야 한다. |

실제 운영 반영 전에는 운영 소스·배포·전체 JSON의 복구 지점을 확보하고, 전체 자료 대조와 사용할 모든 기기의 호환성을 확인해야 한다. 승인된 독립 운영 저장·revision 충돌·응답 유실 재시도·재조회·Docs 실패 후 재시도·Calendar 독립 대상 검증은 별도 필수 작업이다. 원본 앱과 원본 Google 파일에는 쓰지 않는다.

실제 휴대전화·오프라인 업데이트·인쇄·스크린리더 검증도 남아 있다. 이 문서와 검토 ZIP 준비를 사용자의 운영 반영 승인으로 해석하지 않는다.

후속 [최신 독립 운영 자료 계산 대조](OPERATING_DATA_RECONCILIATION.md)에서 38건·11개월의 기존/새 공유/GAS 계산 차이 0건을 확인했다. 과거 추정 표시 30건의 원래 고지서·계약 확인과 실제 저장·복구 검증은 남아 있다. 이 후속 읽기 검사는 기존 ZIP과 압축본 검사 기록을 변경하지 않는다.
